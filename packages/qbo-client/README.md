# @easytestdata/qbo-client

Realistic test data for QuickBooks Online sandboxes.

The QuickBooks Online (QBO) API client behind EasyTestData: loads a plan generated by
[`@easytestdata/core`](https://www.npmjs.com/package/@easytestdata/core) into a QBO sandbox
company in dependency order, and purges it again. Most people want the
[`easytestdata`](https://www.npmjs.com/package/easytestdata) CLI, which wraps this package and
handles OAuth for you.

[![npm](https://img.shields.io/npm/v/@easytestdata/qbo-client)](https://www.npmjs.com/package/@easytestdata/qbo-client)
[![License: Apache-2.0](https://img.shields.io/badge/License-Apache--2.0-blue.svg)](LICENSE)

> **Sandbox only by design.** `QboClient` only talks to
> `https://sandbox-quickbooks.api.intuit.com` and throws if given any other API base URL. It will
> never write synthetic data into a production QBO company.

## Install

```bash
npm install @easytestdata/qbo-client @easytestdata/core
```

Requires Node.js 22.13 or later.

## Quick start

You need an Intuit developer app (development keys), a QBO sandbox company, and OAuth tokens
for it (`npx easytestdata auth` obtains and saves them to `.easytestdata.json`).

```js
import fs from "node:fs";
import { generate } from "@easytestdata/core";
import { QboClient, loadPlanIntoQbo, purgeTransactions } from "@easytestdata/qbo-client";

const client = new QboClient({
  qboRealmId: process.env.QBO_REALM_ID,
  qboClientId: process.env.QBO_CLIENT_ID,
  qboClientSecret: process.env.QBO_CLIENT_SECRET,
  qboRefreshToken: process.env.QBO_REFRESH_TOKEN,
  // Called when Intuit rotates the refresh token: persist it or you will have to re-authorize.
  // Write it somewhere private (a secrets store, an encrypted file); never log it.
  onTokenRefresh: ({ refreshToken }) =>
    fs.writeFileSync(".qbo-refresh-token", refreshToken, { mode: 0o600 })
});

const plan = generate({ template: "saas", preset: "healthy-small", seed: 42 });

// config defaults to the plan's industry template; pass resolveConfig(...) to override ratios.
const result = await loadPlanIntoQbo(client, plan, null, ({ step, totalSteps, message }) =>
  console.log(`[${step}/${totalSteps}] ${message}`)
);
console.log(result.counts, result.failures.length);

// Later: delete/inactivate everything tagged "EZTD" (the default tag).
await purgeTransactions(client, { mode: "generated", tag: plan.tag });
```

## How generated data is identified

Every record EasyTestData creates carries the plan tag (default `EZTD`):

| Record        | Tag field                         |
| ------------- | --------------------------------- |
| Transactions  | `PrivateNote` and/or `DocNumber`  |
| Customers     | `Notes` (`EZTD-CUST-001 ...`)     |
| Vendors       | `AcctNum` (`EZTD-VEND-001`)       |
| Employees     | `EmployeeNumber` (`EZTD-EMP-001`) |
| Service items | `Description`                     |

`purgeTransactions(client, { mode: "generated", tag })` deletes the tagged transactions and
inactivates the tagged customers, vendors, employees and items (QBO does not allow deleting
them). Accounts created during a load stay. Display names are realistic and are never used to
decide what to purge, so hand-made records are untouched; datasets loaded with different tags
are purged separately. `mode: "all"` deletes every transaction and inactivates all master data
in the sandbox company.

## API

- `new QboClient(options)`: HTTP wrapper with OAuth token refresh, rate limiting (450 requests
  per 61 seconds), retries and the sandbox guard.
- `loadPlanIntoQbo(client, plan, config?, emit, signal)`: creates accounts, master data, service
  items and all transaction types in dependency order.
- `purgeTransactions(client, { mode, tag }, emit, signal)`: ordered, tag-filtered deletion.
- `batchCreate` / `batchDelete` / `batchUpdate`: chunked batch operations (30 items per call).
- `tagMatches(value, tag)`, `MASTER_DATA_TAG_FIELDS`, `QBO_SANDBOX_BASE_URL`.
